# A200 기상전광판 — 실행 안내

최종 동작 확인: 2026-08-10 (월)
확인된 상태: 연속 폴링, 센서 응답 14.2초 안정

---

## 1. 필요한 파일 (2개)

같은 폴더에 두 파일만 있으면 됩니다.

```
serve.py      프록시 서버 + 센서 폴러
board.html    전광판 화면
```

---

## 2. 실행

PowerShell 에서 **반드시 폴더로 이동한 뒤** 실행합니다.

```
cd D:\연구소\...\13. 기상전광판\A200_외장센서
python serve.py 0
```

> **탐색기에서 더블클릭하지 마세요.**
> 작업 폴더가 달라져 board.html 을 못 찾습니다.

정상 기동 화면:

```
================================================================
  전광판 서버 v3   [연속] 쉬지 않고 읽습니다 - 최고 속도
================================================================
  플레이어 192.168.0.16      이 PC 192.168.0.9

  PlayerMaster 웹페이지 창 주소
     http://192.168.0.9:8000/board.html
----------------------------------------------------------------
  읽는 중 /api/csensor.json ... 27.6 C   51.5 %   (14.2s)
  읽는 중 /api/csensor.json ... 27.5 C   51.6 %   (14.2s)
```

이 창은 **켜둔 채로** 두어야 합니다. 닫으면 화면도 끊깁니다.

PlayerMaster 웹페이지 창 주소:

```
http://192.168.0.9:8000/board.html?v=9
```

`?v=9` 는 캐시 우회입니다. **board.html 을 수정할 때마다 숫자를 바꾸세요.**
안 바꾸면 플레이어가 옛 버전을 그대로 씁니다.

## 3. 폴링 속도

| 실행 | 센서 갱신 | 화면 반영 | 최악 지연 |
|---|---|---|---|
| `python serve.py 0` | 14초 | 3.5초 | 약 18초 |
| `python serve.py 20` | 20초 | 5초 | 25초 |
| `python serve.py 60` | 60초 | 15초 | 75초 |
| `python serve.py` | 300초 | 15초 | 315초 |

화면 주기는 **자동**입니다. serve.py 가 자기 주기를 응답에 실어 보내고
board.html 이 그 1/4 로 맞춥니다. 화면 파일을 따로 고칠 필요가 없습니다.

센서 한 번 읽는 데 14.2초가 걸리므로 20초 미만은 의미가 없습니다.
연속(`0`)이 사실상 최고 속도입니다.

## 4. 명령 목록

| 명령 | 용도 |
|---|---|
| `python serve.py 0` | **운영/테스트.** 연속 폴링, 최고 속도 |
| `python serve.py 60` | 1분 주기 |
| `python serve.py` | 5분 주기 |
| `python serve.py demo` | 가짜 값으로 6가지 상태 순회. 센서 없이 화면만 확인 |
| `python serve.py watch` | 센서만 연속 관찰, 변화량 표시. **웹서버 안 뜸** |
| `python serve.py bench` | 접근 방식별 속도 실측 (몇 분 소요) |
| `python serve.py find` | IP 가 바뀌었을 때 대역을 훑어 플레이어 검색 |
| `python serve.py programs` | 재생 중인 프로그램 및 목록 조회 |
| `python serve.py play 이름.vsn` | 프로그램 전환 후 센서 재시험 |
| `python serve.py config` | 설정 조회 (info / boardconfig / sensor_source) |
| `python serve.py probe` | 엔드포인트 전체 검사 |
| `python serve.py slow` | csensor 를 90초까지 기다려 봄 |
| `python serve.py source0` | 센서 소스를 0(직결)으로 강제 설정 |

`bench` `watch` `probe` `slow` `find` `config` `programs` 는 **검사 후 종료**합니다.
웹서버가 뜨지 않으므로 화면은 동작하지 않습니다.

## 5. 반드시 지킬 것 세 가지

오늘 하루를 날린 원인이 전부 여기 있습니다.

### 5-1. serve.py 를 두 개 이상 띄우지 마세요

두 프로세스가 같은 센서를 동시에 두드리면 응답이 14초에서 28초, 53초로
늘어지다 아예 실패합니다.

현재 코드는 Windows 에서 중복 실행을 차단하지만, 확인하려면:

```
Get-Process python,py -ErrorAction SilentlyContinue
```

정리:

```
taskkill /F /IM python.exe
taskkill /F /IM py.exe
```

### 5-2. board.html 의 URLS 에 플레이어 주소를 넣지 마세요

```javascript
var URLS=['/sensor'];          // 올바름
```

board.html 은 **플레이어 안에서** 실행됩니다. 따라서 `localhost` 는
플레이어 자신입니다. 여기에 플레이어 주소를 넣으면:

```
serve.py 가 센서를 못 읽음
  → /sensor 가 502
    → 화면이 다음 후보로 넘어가 플레이어 csensor 를 직접 호출
      → 그 요청이 센서를 14~45초 점유
        → serve.py 요청이 뒤로 밀려 타임아웃
          → /sensor 계속 502  (무한 반복)
```

**한 번 실패하면 스스로 실패를 유지합니다.** 재부팅해도 프로그램이 자동
재생되면서 다시 시작됩니다.

플레이어 안에 파일을 올려 `file://` 로 직접 구동할 때만
`URLS=['/api/csensor.json']` 로 바꿉니다 (그때는 프록시가 없음).

### 5-3. 화면 수정 후에는 ?v= 숫자를 바꾸세요

이 펌웨어(1.69.5)는 웹 캐시 모드 제어 API 가 없습니다(1.71.6+ 필요).
주소를 바꾸는 것이 유일한 캐시 우회입니다.

```
http://192.168.0.9:8000/board.html?v=9
http://192.168.0.9:8000/board.html?v=10   ← 수정 후
```

```
http://192.168.0.9:8000/board.html?debug=1&v=9
```

| 항목 | 의미 |
|---|---|

`#` 만 늘고 `chg` 가 안 늘면 서버 캐시가 갱신되지 않는 것입니다.

## 7. 설정값

### serve.py 상단

```python
PLAYER_IP  = "192.168.0.16"   # 플레이어 IP
PORT       = 8000             # 이 PC 의 웹서버 포트
POLL_SEC   = 300              # 기본 폴링 주기 (명령행 인자로 덮어씀)
FAIL_SEC   = 60               # 실패 시 재시도 간격
TOTAL      = 60               # 한 요청 전체 제한
IDLE       = 45               # 응답 대기 (실측 14.2초 + 3배 여유)
TRY_SINGLE = False            # ?type= 단일 조회. 1.70.4 이상에서만 True
```

### board.html 상단

```javascript
var POLL   = 8000;    // 서버가 주기를 안 알려줄 때의 기본값 (ms)
var MINPOLL = 2000, MAXPOLL = 15000;   // 자동 조정 범위
var MAXAGE = 900;     // 이 초수보다 오래된 값은 '센서 없음' 처리
var T_LOW = 10, T_HIGH = 33;   // 온도 임계값
var H_LOW = 20, H_HIGH = 80;   // 습도 임계값
var DEAD  = 0.5;               // 히스테리시스
var DIGIT = 13;                // 도트 숫자 높이 (vmin)
var IMG   = false;             // true 로 바꾸면 이미지 파일 사용
```

### 이미지 파일로 바꾸려면

`board.html` 과 같은 폴더에 `weather.files/` 를 만들고 6개를 넣습니다.

```
hot_humid.png   hot.png   humid.png
cold.png        dry.png   normal.png
```

그다음 `var IMG = false;` → `true`.
파일이 없으면 자동으로 내장 그래픽으로 되돌아갑니다.

## 8. 센서를 못 읽을 때

순서대로 확인하세요.

**1) serve.py 가 여러 개 떠 있는가** — 5-1 참조. 가장 흔한 원인입니다.

**2) 플레이어가 board.html 구버전을 물고 있는가** — 5-2 참조.
   `Ctrl+C` 로 serve.py 를 끄면 플레이어가 페이지를 못 불러오므로
   두드림이 멈춥니다. 이 상태에서 브라우저로 확인:

```
http://192.168.0.16/api/csensor.json?t=99
```

   여기서 값이 나오면 센서는 정상입니다.

**3) IP 가 바뀌었는가**

```
python serve.py find
```

**4) 설정이 바뀌었는가**

```
python serve.py config
```

   `sensor_source` 의 `display` 가 0(직결)이어야 합니다.
   아니면 `python serve.py source0`.

**5) 그래도 안 되면** 플레이어 전원 뽑기 30초 → 재부팅 → 2분 대기 →
   브라우저로 2)번 확인. 그래도 무응답이면 RJ11 커넥터 양단 재체결.

```

센서 API    GET /api/csensor.json
            {"humidity":51.5,"temperature":27.6}
            응답 14.2초 (실측, 편차 거의 없음)
```

### 왜 14초나 걸리는가

`csensor.json` 은 RJ11 버스의 **모든 센서 종류**(PM2.5, PM10, 밝기, 습도,
연기, 소음, 온도)를 훑습니다. 여기에는 온습도만 달려 있으므로 없는 센서
5종을 매번 기다렸다 포기합니다.

문서에서 단일 조회(`?type=`)를 "responsive interface" 라고 따로 표현한 것도
전체 조회가 애초에 느리게 설계되었다는 뜻입니다.

**14초보다 빠르게 하는 유일한 방법은 펌웨어를 1.70.4 이상으로 올리는 것**
입니다. 그러면 `?type=temperature` 가 열려 2~3초대가 됩니다.
코드는 이미 대응되어 있으므로 `TRY_SINGLE = True` 로만 바꾸면 됩니다.

## 11. 알아둘 사항

**플레이어는 CORS 헤더를 주지 않습니다.** 그래서 브라우저가 플레이어 API 를
직접 못 읽고, serve.py 프록시가 반드시 필요합니다.

**PlayerMaster 미리보기는 Chromium 75 입니다.** clamp() / flex gap / inset /
aspect-ratio 속성 / Promise.allSettled / AbortController 가 없습니다.
board.html 은 이를 피해 ES5 로만 작성되어 있습니다. 수정 시 주의하세요.

**센서 응답 14초는 화면에 드러나지 않습니다.** 백그라운드 스레드가 미리
읽어두고 화면은 캐시만 읽습니다.

**5분 폴링에서는 화면도 5분에 한 번만 바뀝니다.** 손으로 센서를 감싸
시험할 때는 `python serve.py 0` 을 쓰세요.
