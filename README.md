## 2. 실행

```
python serve.py
```

시작할 때 센서를 한 번 읽느라 **15초쯤 멈춰 있는 것이 정상**입니다.

정상 기동 화면:

```
O  /api/csensor.json:80   12.7s  {"humidity":45.9,"temperature":31.8}
      HTTP/1.1 200 OK
----------------------------------------------------------------
  사용 가능: /api/csensor.json    폴링 300초 주기로 시작. 종료는 Ctrl+C
  31.5 C   46.6 %   (28.5s)
```

이 창은 **켜둔 채로** 두어야 합니다. 닫으면 화면도 끊깁니다.

그다음 PlayerMaster 웹페이지 창 주소:

```
http://192.168.0.9:8000/board.html
```

`192.168.0.9` 는 PC 의 IP 입니다. 바뀌었으면 serve.py 실행 시 화면에 표시되는
주소를 그대로 쓰세요.

## 3. 명령 목록

| 명령 | 용도 |
|---|---|
| `python serve.py` | **운영.** 5분 폴링 + 웹서버 |
| `python serve.py fast` | 테스트. 20초 폴링 — 센서 반응을 화면에서 확인할 때 |
| `python serve.py watch` | 센서만 연속 관찰. 변화량 표시. 웹서버 없음 |
| `python serve.py demo` | 가짜 값으로 6가지 상태 순회. 센서 없이 화면만 확인 |
| `python serve.py config` | 플레이어 설정 조회 (info / boardconfig / sensor_source) |
| `python serve.py probe` | 엔드포인트 전체 검사 (느림) |
| `python serve.py slow` | csensor 를 90초까지 기다려 봄 |
| `python serve.py source0` | 센서 소스를 0(직결)으로 강제 설정 |
| `python serve.py find` | **IP 가 바뀌었을 때.** 같은 대역을 훑어 플레이어를 찾음 |

## 4. 화면 디버그

주소 뒤에 `?debug=1` 을 붙이면 우측 하단에 표시됩니다.

```
http://192.168.0.9:8000/board.html?debug=1
```

```
31.6/74.6  age20s  #7  chg3
```

| 항목 | 의미 |
|---|---|
| `age` | 이 값이 몇 초 전 것인지 |
| `#` | 화면이 서버를 읽은 횟수 |
| `chg` | 값이 실제로 바뀐 횟수 |

`#` 만 늘고 `chg` 가 안 늘면 서버 캐시가 갱신되지 않는 것입니다.

파일을 수정했는데 화면이 그대로면 PlayerMaster 캐시입니다.
주소 뒤 숫자를 바꿔 붙이세요: `?v=2`, `?v=3` …

## 5. 설정값 위치

### serve.py 상단

```python
PLAYER_IP = "192.168.0.16"   # 플레이어 IP
PORT      = 8000             # 이 PC 의 웹서버 포트
POLL_SEC  = 300              # 센서 폴링 주기 (초)
FAIL_SEC  = 60               # 실패 시 재시도 간격
TOTAL     = 45               # 한 요청 전체 제한
IDLE      = 30               # 응답 대기 (실측 13~16초 + 여유)
```

### board.html 상단

```javascript
var POLL   = 30000;   // 프록시 캐시 읽는 주기 (ms)
var MAXAGE = 900;     // 이 초수보다 오래된 값은 '센서 없음' 처리
var T_LOW = 10, T_HIGH = 33;   // 온도 임계값
var H_LOW = 20, H_HIGH = 80;   // 습도 임계값
var DEAD  = 0.5;               // 히스테리시스
var IMG   = false;             // true 로 바꾸면 이미지 파일 사용
```

### 이미지 파일로 바꾸려면

`board.html` 과 같은 폴더에 `weather.files/` 를 만들고 6개를 넣습니다.

```
hot_humid.png   hot.png   humid.png
cold.png        dry.png   normal.png
```

그다음 `var IMG = false;` → `true`.
파일이 없으면 자동으로 내장 그래픽으로 되돌아갑니다.

## 5-1. 센서를 못 읽을 때

순서대로 확인하세요.

1. **IP 가 바뀌었는지** — 가장 흔한 원인입니다. 주말이나 정전 후 DHCP 임대가
   만료되면 주소가 바뀝니다. 실제로 한 번 겪었습니다 (192.168.0.144 → .16).

   ```
   python serve.py find
   ```

   찾으면 serve.py 상단 `PLAYER_IP` 를 그 값으로 바꾸세요.
   `python serve.py` 는 기동 시 자동으로 재검색하지만, 설정을 고쳐두면 빨라집니다.

2. **응답이 더 느려졌는지**

   ```
   python serve.py slow
   ```

   최대 90초까지 기다립니다. 여기서 성공하면 `IDLE` 값을 그 시간보다 크게 잡으세요.

3. **설정이 바뀌었는지**

   ```
   python serve.py config
   ```

   `sensor_source` 의 `display` 가 0(직결)인지 확인합니다.
   0 이 아니면 `python serve.py source0`.

4. **그래도 안 되면** RJ11 커넥터를 양단 모두 뽑았다 딸깍 소리가 나게 다시 꽂기.

## 6. 알아둘 사항

**센서 응답이 13~16초 걸립니다.** 고장이 아니라 이 장비의 특성입니다.
백그라운드 스레드가 미리 읽어두므로 화면은 기다리지 않습니다.

**폴링 5분이면 화면도 5분에 한 번만 바뀝니다.** 손으로 센서를 감싸 테스트할 때는
`python serve.py fast` 를 쓰세요.

**플레이어는 CORS 헤더를 주지 않습니다.** 그래서 브라우저가 플레이어 API 를
직접 못 읽고, serve.py 프록시가 반드시 필요합니다.

**PlayerMaster 미리보기는 Chromium 75 입니다.** clamp() / flex gap / inset /
aspect-ratio 속성 / Promise.allSettled / AbortController 가 없습니다.
board.html 은 이를 피해 ES5 로만 작성되어 있습니다. 수정 시 주의하세요.

**화면 해상도는 384 x 432 세로형** 기준으로 맞춰져 있습니다.
도트 숫자 80px, 상태 문구 46px, 그래픽 159px.
